# 2026-09-20 GitHub状态面板实施计划

**创建时间：** 2026-09-20 23:46:43（Asia/Shanghai，UTC+08:00）
**更新时间：** 2026-09-21 08:59:01（Asia/Shanghai，UTC+08:00）

## 目标

在 `/status` 页面增加 AbelTomato GitHub Contributions 贡献热力图，展示过去一年的每日贡献格、贡献等级、总贡献数和同步时间；侧边栏的最后活跃时间复用同一份缓存数据。

## 范围与方案

- GitHub 用户固定为 `AbelTomato`，博客仓库固定为 `AbelTomato/AbelTomato.github.io`。
- GitHub Actions 在既有 WakaTime、LeetCode 数据同步步骤后，调用 GitHub REST API 和 GraphQL `contributionCalendar`，并生成 `src/features/github/data/github-stats.json`。
- 状态页 React 组件从本站部署的静态 JSON 读取每日贡献数据并自行绘制热力图，不加载 GitHub 外部图片。
- 同步脚本使用 GitHub Actions 内置的 `GITHUB_TOKEN` 请求 REST API 和 GraphQL；前端不请求 `api.github.com`。
- 远程请求失败时保留已有缓存，不阻断已有缓存场景下的构建；不新增依赖，不保存任何令牌。

## 任务拆分

1. 定义 GitHub Contributions 数据契约；先以 Vitest 测试覆盖 GraphQL 每日数据解析、等级转换、日期排序和非法字段降级。
2. 实现同步脚本，获取用户、公开仓库、博客仓库最新提交和 GraphQL 贡献日历，写入静态 JSON。
3. 实现静态 JSON 加载 hook 和 GitHub Contributions 热力图，接入 `/status` 页面，并复用现有 Card、加载和错误状态组件。
4. 修改侧边栏 GitHub 数据 hook，使其从静态缓存读取并在没有缓存时间时显示占位符。
5. 接入部署工作流和脚本文档；执行定向单元测试、`pnpm run check` 与 `pnpm run build`。

## 风险与回滚

- GitHub API 或 GraphQL 限流、超时：使用 `GITHUB_TOKEN` 提高 Actions API 配额，且同步失败时保留上次成功缓存；前端缓存为空时显示本地数据不可用提示，不加载外部图片。
- API 字段空缺或结构变化：仅映射稳定字段，转换逻辑覆盖空值并由单元测试保护。
- 面板出现视觉或构建问题：移除 `GithubStatusPanel` 页面渲染、恢复旧 hook 与工作流变更即可回滚；缓存 JSON 保留不会阻碍构建。
