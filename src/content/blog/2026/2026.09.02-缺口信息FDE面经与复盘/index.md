## 如何区分skill的好坏

答：应当有清晰的说明和要求，明确约束Agent对于工具的调用，让其能够稳定地完成任务

首先需要确定什么叫做skill

说实话在今天之前我一直是一种似懂非懂的状态，之前一直认为是一种规范的Prompt，现在看来我的思想仍然停留在Prompt Engineering时代

没有skill的LLM是只会空谈的，给LLM装上skill，就相当于给它装上了手脚，从而真正意义上地拥有执行、完成规范化任务的能力

一个完整的Agent Skill通常分为三大部分：

- **元数据描述**：相当于给LLM看的说明书，用自然语言描述这个Skill是干嘛的，参数如何
- **执行逻辑**：就是面向系统的代码，可以是函数、API接口、数据库查询
- **返回值解析**：执行完之后将结果重新格式化，返回给LLM进行决策

Skill可以分为两类：

- **Semantic Skill**：类似于我之前的那种理解，本质就是一段精心设计的Prompt+LLM交互流程；适用于处理非结构化文本、自然语言转换、摘要提取
- **Native Skill**：传统的硬编码；适用于执行精准计算、文件I/O、数据库读写、调用API

Skill在Agent中的工作流，可以分为四阶段：意图识别与选择、参数提取、本地执行、状态反馈及链式调用

为什么纯Prompt的Skill模式在很多情况下变得不可行了呢？首先在这种情况下，Agent无法直接执行操作，且容易产生为人诟病的幻觉，所以在现代Agent中，必须赋予其直接执行代码的能力

回到问题，如何定义个Skill的好坏？从四个方面分析

- **语义可达性**：也就是LLM能否在正确的时机调用它，像是名字叫做`process_data`，然后description是“处理用户输入的数据”，语义模糊不清，LLM不知道何时调用，容易引发幻觉调用；
  
  而一个好的Skill应当有**单一职责**和**边界清晰**两大特点，描述中写清楚何时应该用以及何时不应该用
- **交互鲁棒性**：核心问题在于参数设计对于LLM来说是否友好，传参错误以及报错时能不能自我调整修复
  
  好的Skill应当**参数扁平化**，入参简单直观，以及有**自愈式报错**能力，执行失败时返回明确且有引导意义的错误信息，便于LLM调整决策
- **执行确定性**：即输入相同的参数，输出结果是否稳定且可预测
  
  好的Skill应当有**幂等性**以及**纯函数倾向**，尽可能保持输入输出可预测，同时做**信息密度优化**，返回值要经过提炼过滤，只保留LLM解决问题所需的关键字，节省Context空间，防止不必要的Compact导致Context模糊甚至丢失
- **安全与隔离性**：确保Agent在执行过程中不会炸掉你的服务器或者删库跑路
  
  好的Skill应当有**严格的输入输出校验**，如利用Pydantic或者JSON Schema，以及**权限控制与沙箱**，高危Skill必须有沙箱隔离，并且设置明确的确认回调

## 情景题

情景：假设甲方是一家做定制产品的公司，例如手机支架、画框之类，现在甲方遇到问题，对于市场上出现的热点产品，甲方需要跟随热点进行产品设计投产，但是对热点的即时性把控不足，询问如何配置AI数字员工的工作方式与流程，实现从热门搜索词搜集，到产品预先设计，再到生产流水线方案生成的全流程自动化

中间有穿插问题：

1.关于对电商与自媒体平台近期热度上升关键词的获取，仍然显得太晚导致无法及时完成生产，如何解决

2.已经定义这个流程应当通过配置skill来解决，你怎么配置这个skill

3.为什么在业务阶段上对skill进行拆分

4.这个skill有没有更大或者更小的颗粒度

其实记得不止这几个问题，但是拷问太多了而且我只录到我自己的声音，只想起来这几个了

### Q1

在这个问题前面其实是对情景题的回答中我说可以看电商平台和社交媒体平台的近期热点词之类

但是显然还是太年轻了，缺乏业务与产品思维

确切来说，真正要解决这个问题，应当具备前瞻思维

等到人家上热搜榜了，你再去做，此时头部商家早就已经生产好成品投入市场了，一步慢步步慢

像是公域热搜榜这种事结果指标而非过程指标，我们应该看的是什么，是高速增词，什么词语在这段时间热度开始上涨，有什么公共事件的发生可能会成为这个诱因

同时要做供应链时效反馈，结合自己的生产周期，比如说设计一天，做出模具一天，生产三天，去倒推最晚的抓取节点

如何更快、更提前地捕捉热点？从被动抓热搜转向主动地捕捉弱信号

首先是监控数据源上移，关注社媒种草信号、跨境与上游平台，甚至同类竞品商家的上新预告

随后是重构评估指标，用变化率取代绝对热度

比如说这样建模：

$$
热度爆发系数 = \frac{今日搜索量 - 前3日均值}{前3日均值} \times 互动率
$$

只要爆发系数超过某个阈值，AI数字员工立刻启动后续流程

然后是AI预研以及模块化设计，像这种标准件，产品结构是高度模块化的

比如说首先可以将支架结构做成标准化的CAD库，最后捕捉到上升热点，AI数字员工只需要将对应的视觉元素做套壳渲染

### Q2

针对这个工业流程，值得注意的是，工业上的约束应当大于创意的优先级

从数据输入到营销创意提取再到工业约束校验最后生成结构化输出，以`hotspot_to_product_design`这个业务流程为例，在标准Agent框架下，可以配置成这样的Skill：

```yaml
skill_name: hotspot_to_product_design
description: 将捕获的社媒/电商突发热点转化为可投产的产品外观与轻量结构方案

# 1. 输入上下文 (Context Input)
inputs:
  - hotspot_keyword: "爆款关键词 (例：多巴胺配色)"
  - visual_references: "抓取到的高赞图片/趋势图 URL 列表"
  - target_product_type: "目标产品品类 (例：桌上型手机支架)"

# 2. 工业约束条件 (Hard Constraints) - 核心重点！
constraints:
  base_mold_id: "STD_HOLDER_V2" # 强制指定通用底座/滑轨规格，AI 只能设计外壳/装饰面
  manufacturing_process: ["UV_PRINTING", "3D_PRINTING_PLA", "LASER_CUTTING"] # 限定生产工艺
  max_dimensions: "150mm x 80mm x 100mm" # 最大尺寸限制
  cost_ceiling_rmb: 8.5 # 算上材料的BOM成本上限

# 3. 核心 Prompt 逻辑 (System Instructions)
prompt_template: |
  你是一名兼具商业敏锐度与工业设计常识的数字员工。
  请根据输入的热点词【{hotspot_keyword}】与视觉参考，执行以下步骤：

  Step 1 [营销特征提炼]:
  - 提取热点词背后的情绪价值（如：解压、复古、赛博朋克）与核心视觉元素（配色方案、标志性图案、纹理）。

  Step 2 [产品外观渲染提示词生成]:
  - 结合标准件【{base_mold_id}】的物理结构，生成用于 Midjourney/Stable Diffusion 的 3D 产品渲染 Prompt。
  - 必须包含材质指定（如：磨砂质感、透明丙烯酸）。

  Step 3 [生产贴图与 CMF 方案生成]:
  - 输出矢量贴图设计尺寸参数（必须适配 {max_dimensions}）。
  - 指定 CMF (Color, Material, Finishing) 色号（Pantone 色号）。

  Step 4 [可行性自检]:
  - 检查设计方案是否超出现有工艺【{manufacturing_process}】。如果超限，自动降级为 UV 彩印方案。

# 4. 结构化输出格式 (JSON Schema Output)
output_format:
  json:
    product_name: "拟定的产品营销名称"
    design_concept: "设计理念（50字内）"
    image_prompt: "SD/MJ渲染图Prompt"
    cmf_spec:
      pantone_colors: ["13-1513 TCX", "16-1360 TCX"]
      surface_process: "表面磨砂UV打印"
    bom_estimate_rmb: 6.2
    is_manufacturable: true
```

### Q3

首先是降低AI的认知负荷，AI的上下文窗口有限，如果拆分为过粗颗粒度，如将一整个业务流程设计为一个Skill，大概率会在某个环节出岔子

然后每个环节需要调用的工具链不同，根据先前所阐述的对Skill好坏区分的标准，就可以知道一口气讲所有工具的权限都塞给一个Skill是不可行的

然后这样拆分，可以在中间设计人工节点，比如说在热词获取和创意设计中间插入一个人工审核节点，避免政治敏感或者其他不当词汇被抓取进入后续流程，造成直接经济损失

还有一个好处是可以在超时或者出问题的环节重试，而不是完整重新跑一遍Skill

最后则是成本与Agent模型选择问题，针对不同的环节，实际上所需的Agent能力是不同的，这样就可以考虑成本与能力问题，合理配置Agent，而不是全程使用昂贵的Agent

### Q4

显然更粗的颗粒度就是全业务流程，使用这个颗粒度优点在于上下文无缝衔接，不需要做Agent状态同步；缺点很显然，流程太长容易幻觉，以及上面提到的那些点

更细的话就是完全遵循单一职责原则，拆到再无可拆，每一个动作作为一个Skill，这个优点在于调配灵活，确定性高，而且还能复用；缺点就是调配流程极其复杂，需要进行频繁的路由和工具切换调用

这场面完也是发现了自己很多的不足，比如对于Agent的了解近乎趋于0，还有缺乏实际业务营销意识，不能快速地根据实际问题给出解决方案
